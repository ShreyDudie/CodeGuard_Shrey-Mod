CodeGuard

Pre-execution safety check for LLM-generated code. Nothing is ever run; no LLM is called.

Drop a file here, or click to choose
.jsonl / .json / .txt / .pdf with {"code": "..."} objects (one after another is fine), .csv with a "code" column, or any code file
Score against an answer key (optional) — compare the system's answers with the expected outputs and get accuracy, precision, recall and more straight away

Answer key: one expected output per snippet, in the same order as the snippets, in this format (a JSON list, or one object per line; CSV and PDF also work):
{"verdict": "block", "categories": ["obfuscated_execution"], "code_language": "sql"}
verdict is required (allow / block, or a 0/1 label); categories, code_language, risk_score and vulnerable_lines are scored when present. An id is optional: if the key and the snippets both carry ids that agree they are matched by id, otherwise by position. If you add the key before dropping the snippets file, it is scored automatically after the scan.

The service remembers the answer it gave to every request (...). Entries are matched by id (if the requests carried one), by code (if the key includes it) or by the order the requests arrived; clear the log just before an evaluation starts.

The safe snippet writes a marker file only if it runs; the unsafe snippet would write a different marker, so that file existing would prove it ran.

Only the harmless files demo/safe_snippet.py (runs) and demo/unsafe_snippet.py (scanned, never executed) are involved. Text you paste on the other tabs is never executed.
